# 视频风格拆解：等距说明动画（Isometric Explainer）

> 这份拆解是 skill 的“设计规范”。每一条都对应到引擎里的具体能力，写故事板时照此执行。
> 如果手头有新的参考视频，先跑 `scripts/analyze_reference.sh`，再用文末的「拆解清单」逐项对照，修正这里的参数。

## 1. 一句话定义
把一个**流程 / 系统 / 概念**放进同一个等距（30°）世界里：先用**线条描摹**出轮廓，再把**组件逐块组装**成实体，然后让**数据/物件沿管道流动**，镜头在一个连续空间里**平滑推拉摇移**，底部始终有**同步字幕**，左上角有**章节标签**。

## 2. 五个核心视觉动作（动画语法）

| # | 动作 | 画面表现 | 作用 | 引擎动作 | 默认时长 |
|---|------|----------|------|----------|----------|
| 1 | 精准线条描摹 | 物体先以浅色细线“画”出全部棱线（像蓝图），角点出现小定位点 | 交代“这里将出现什么”，建立期待 | `trace` / `build` 前 45% | 1.2 s |
| 2 | 组件组装 | 实体部件从上方逐块落下，带轻微回弹（easeOutBack），描摹线随之淡出 | 展示系统由什么构成；层数=复杂度 | `assemble` / `build` 后 60% | 1.0 s |
| 3 | 管道连接 | 节点之间的管道从起点“长”向终点，末端出现箭头 | 交代关系与方向 | `link` | 0.9 s |
| 4 | 可见流动 | 小圆点 / 小立方体 / 带字标签沿管道连续移动，管道提亮 | 让抽象的“数据/请求/物料”可见 | `flow` | 3 s 或 `until: end` |
| 5 | 强调 | 节点底部出现扩散的菱形光圈；侧边弹出说明气泡 | 把注意力钉在关键步骤 | `highlight` / `callout` | 2–5 s |

**节奏规律**：一个镜头 = “出现 → 连接 → 流动 → 强调”，四拍。新元素出现永远先描摹后组装，从不“凭空闪现”。

## 3. 运镜（连贯、无硬切）
- **单一世界、单一镜头**：全片不切镜，所有场景发生在同一张等距地图上；“换场景”= 镜头平移 + 缩放到新的焦点组。
- 每个镜头开头 1.4 s 用 easeInOutCubic **从上一镜头的终点过渡**到新取景（缩放在对数空间插值，避免“忽快忽慢”）。
- 镜头内持续 **4–6% 的缓慢推近（drift）**，画面永远在“呼吸”，不会死板静止。
- 取景 = 焦点节点的包围盒 × pad（1.2–1.9）；内容整体略上移，给底部字幕留出空间。
- **聚焦压暗**（`dim: true`）：非焦点元素降到 28% 不透明度，讲局部时不丢全局。
- 开场：全景俯视 + 标题卡；结尾：拉回全景，全部管道同时流动，形成“系统在运转”的总结画面。

## 4. 构图与几何
- 投影：标准等距，x 轴向右下、y 轴向左下、z 轴向上；1 世界单位 = 44 px（`meta.unit`）。
- 三面明暗：顶面最亮（+32%）、左前面基色（+5%）、右侧面最暗（−22%），统一 2.4 px 深色描边，圆角连接——“扁平插画 + 描边”的说明书质感。
- **底座平台**（platform）划分区域（如“客户端 / 服务端”“离线 / 在线”），区域名印在平台顶面上，平台后沿留 ~1.5 单位空白放标题。
- 地面有极淡的等距网格（每 4 格加粗），既是“工程图纸”的暗示，也让运镜有参照物。
- 主流程沿一个方向推进（屏幕左上 → 右下 或 左 → 右），管道走正交折线（xy / yx），跨区域的返回路径用空中弧线（arc）避免交叉。

## 5. 元件库（节点类型）
`box` 方块 · `block/stack` 叠层块 · `server` 机柜（带插槽和指示灯） · `database` 叠层圆柱 · `cylinder` 圆柱 · `screen` 显示器/客户端 · `doc` 文档叠页 · `person` 人物 · `cloud` 云 · `chip` 芯片/模型/处理器 · `ai/model` 带发光球的 AI 模型 · `gate` 门/网关 · `platform` 区域底座。
顶面可印图标（emoji 或 1–2 个字符：`icon`）。复杂度靠 `layers` 体现——组装时一层一层落下。

## 6. 文字层级
1. **标题卡**（开场/结尾）：kicker 小字（强调色、宽字距）+ 92 px 粗标题 + 副标题。
2. **章节标签**（左上）：`01 · 用户提问`，强调色左边条，随镜头切换滑入。
3. **节点名牌**：组装完成时从节点上方升起，虚线引线指向节点顶部；可带步骤序号（`step`）。
4. **流动标签**：跟着粒子走的胶囊小标签（“问题”“答案”“Q”）。
5. **说明气泡**：两行（粗体结论 + 细体解释），左侧强调色条，弹性弹出。
6. **字幕**：底部居中半透明深色圆角底，40 px，按句号/问号切句、超长按逗号再切，每句的显示时长按字数比例分配。

## 7. 色彩
- 背景 + 网格 + 墨线 + 3 个功能色（primary 主体、secondary 存储/辅助、accent 流动/强调）+ success/danger。
- 流动的东西一律用 accent（或语义色：返回结果用 success），静态结构用 primary/secondary，**让“动的”与“不动的”在颜色上分开**。
- 预设：`blueprint`（深蓝图纸）· `paper`（米白纸张）· `mint` · `sunset` · `mono`，也可传自定义对象。

## 8. 时长与信息密度
- 中文字幕 ≤ 4.5 字/秒（英文 ≤ 15 字符/秒），每个镜头 5–10 s，60 s 视频约 6–8 个镜头。
- 每个镜头只新增 1–3 个元素；每个镜头只讲一件事。
- 有旁白时，以旁白时长为准（镜头 = 音频 + 0.6 s），画面动作按比例落在旁白关键词附近。

## 9. 叙事结构模板
1. **钩子/标题**（5 s）：全景 + 标题卡，平台线条描摹。
2. **起点**（6–8 s）：谁发起、要解决什么问题。
3. **组件逐个登场**（每个 6–9 s）：描摹 → 组装 → 连接 → 流动 → 强调。
4. **关键机制**（8–10 s）：highlight + callout，说清“为什么”。
5. **闭环/结果**（6–8 s）：返回路径（弧线）+ 结果气泡。
6. **总结**（6–8 s）：拉回全景，全部管道循环流动，一句话总结。

## 拆解清单（分析新参考视频时逐项填写）
- [ ] 总时长 / 分辨率 / 帧率 / 是否有旁白、BGM、内嵌字幕（`info.txt`）
- [ ] 硬切数量（`cuts.txt`）——等距说明动画通常 0–2 个硬切，主要靠运镜
- [ ] 每 2 秒采样（`every2s/`）：记录每段的焦点对象、缩放级别、运动方向
- [ ] 元件清单：出现了哪些物体？映射到哪种节点类型？有无需要新增的类型
- [ ] 出场方式：描摹 → 组装？还是淡入/缩放？组装时部件从哪个方向来
- [ ] 流动表现：粒子形状、颜色、速度、是否带标签
- [ ] 文字：字幕位置/字号/底色，名牌样式，章节标签
- [ ] 调色：背景、墨线、3 个主功能色（取色后写成自定义 palette）
- [ ] 节奏：每个镜头时长、每秒字数
- [ ] 把以上差异写回 `meta`（palette / unit / lineWidth / captionSize / cameraDrift / dropHeight）
